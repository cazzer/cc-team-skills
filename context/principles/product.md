# Product Principles

## User value

- Every feature should have a clear answer to "who wants this and why?"
- Ship the smallest thing that delivers value. Iterate from there.
- Measure outcomes, not output. Features shipped means nothing if nobody uses them.

## Decision making

- Reversible decisions: move fast. Irreversible decisions: move carefully.
- When in doubt, talk to users. Assumptions compound.
- Say no to most things. Focus is saying no to good ideas so you can say yes to great ones.

## Quality

- Bugs in core flows are emergencies. Bugs in edge cases are backlog.
- User-facing copy is product. Treat it with the same care as design.
- Performance is a feature. Slow software feels broken.

## Growth

- Distribution is part of the product. How do users find this? How do they share it?
- Reduce friction at every step. Every click, every form field, every confirmation dialog is a potential drop-off.
- Social proof and public artifacts drive inbound. Make outputs shareable by default.

## Scope management

- Cut scope, not corners. Fewer features done well beats many features done poorly.
- V1 doesn't need to be perfect. It needs to be useful and correct.
- If a feature needs a 10-minute explanation, it's too complex.
